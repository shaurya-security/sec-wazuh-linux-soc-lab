SOC LAB — LESSONS LEARNED
=========================

Recovery Exercise Gaps
----------------------

1. Endpoint isolation

The compromised Linux endpoint was not isolated immediately after
the compromise was detected.

The endpoint remained available during evidence collection and
recovery activities.

Lesson:
In a production incident, the compromised endpoint should be
isolated from the network as part of containment while preserving
the evidence required for investigation.

2. Compromised endpoint lifecycle

The original compromised Linux endpoint has not yet been removed.

Evidence was collected and the replacement endpoint was provisioned
from the known-good baseline AMI, but the compromised instance remains
in the environment.

Lesson:
After evidence preservation and recovery validation are complete,
the compromised endpoint should be stopped/terminated according to
the incident-response procedure and the action documented.

3. Post-recovery Wazuh telemetry validation

Log ingestion from the recovered endpoint to the Wazuh manager/indexer
has not yet been independently verified.

The recovered endpoint was provisioned from the known-good baseline
AMI and passed the targeted post-recovery persistence assessment, but
end-to-end Wazuh telemetry validation was not completed as part of
this exercise.

Lesson:
A future exercise should verify:
  - Wazuh agent connectivity
  - log ingestion by the manager
  - event visibility in the Wazuh indexer
  - detection/correlation functionality
  - successful controlled detection after recovery

4. Recovery process improvement

The exercise demonstrated that a known-good endpoint AMI can be used
to rapidly provision a replacement endpoint after compromise.

Future projects should incorporate explicit containment, compromised
host lifecycle management, and post-recovery telemetry validation
into the recovery procedure.
